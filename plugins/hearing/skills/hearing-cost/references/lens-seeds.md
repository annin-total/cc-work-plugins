# 観点の種（確認日 2026-10-02）

出発点にすぎない。各観点は「collect の集計 JSON のどこを見るか」と「誤検知の注意」だけを書く。根拠の多くは単一ユーザーの報告や二次情報なので、断定せず確度は「推定」止まりにする。

## 重い寄りになりやすい（影響が大きい順の目安）
- 長時間セッション・自動 compact: 1 ターンごとに全会話が再送される。セッション長、ターン数、キャッシュ読み込み量の大きさに、`context_ops` の区切り操作（clear・手動 compact・自動 compact）の回数を、セッション数と長さに照らして見る。回数に良し悪しは無い。自動 compact が多い（`auto_compact_pre_tokens` が大きい）のは文脈を限界まで膨らませている兆候、手動の区切りが少なく長いセッション（`longest_sessions`）は改善余地の候補。自動 compact のしきい値は `settings` の設定値で確認する（無ければ既定）。誤検知: 読み込みは軽いので量が多いだけで重いとは言わない。版によっては compact の記録が無く（`by_version`）、0 回とは限らない。`/rewind`・起動オプションでの再開は数えていない。
- キャッシュの失効・破壊: 休憩後（5 分／1 時間超）やモデル・effort の切り替え直後に、キャッシュ書き込みが跳ねる。書き込みと読み込みの比、モデルの切り替え回数（`model_change`）や effort の切り替えを見る。誤検知: 新しい作業の開始でも書き込みは増える。
- サブエージェント・並列実行: 親のキャッシュを読まず、短い TTL で再書き込みが多い。sidechain 分のキャッシュ書き込みと全体に占める割合を見る。誤検知: 必要な分担なら避けられない。
- 高いファミリーの常用: ファミリー別のトークン量と比率を見る。誤検知: 難しい作業なら妥当。補助モデルの消費は履歴に出ない（transcript 外の消費の注記を見る）。
- effort・拡張思考: effort が高い行の比率、出力トークンの多さを見る。誤検知: effort が記録されない古い版は「記録なし」であり「低い」ではない。効果の大きさは情報源で割れている。

## 発生すると大きい（頻度は低い）
- 無人・自動実行: `automation` の起動のしかた別（`claude -p`・SDK は `entrypoint` が `sdk-cli`・`sdk-py`）のセッション数・API 呼び出し数・トークン量、ターンの出どころ（`turn_origin`・`prompt_source`）、定期実行系（`ScheduleWakeup`・`Cron*`・`/loop`・`/schedule`）の回数を見る。誤検知: 値の意味は一部未確認で、記録の無い版は「記録なし」。この端末の外（CI・クラウド）の実行は見えない。利用者談で補う。
- 版に依存するキャッシュ異常: 版別のキャッシュ読み込みの比率が極端に低くないか。現行版で再発するかは未確認。
- 大きなツール結果: tool 結果の文字数の上位、ツール種別・拡張子の分布を見る。一度入ると以後の全ターンで再送される。誤検知: 単発の大きさは文字数でしか分からない。
- MCP 定義の常駐: MCP サーバ数、セッション開始直後のキャッシュ書き込みを見る。ツール検索が既定の版では寄与は小さく、ゲートウェイ経由では大きくなりうる。

## ほか
- transcript 外の消費: cost-state と assistant 集計の差。差が大きければ補助モデルの消費を注記する。
- スキルの使われ方: 冗長なワークフローのスキルの多用、無関係な作業での発火、導入数・description の多さによる常駐量を見る。誤検知: 起動回数は distinct で数える。常駐量は小さいことが多い。
- CLAUDE.md の肥大: 初回ターンのキャッシュ書き込みの大きさ。通常サイズなら寄与は小さい。

これに縛られず発散してよい。
