# ヒアリングの手引き

このスキルの本体は、履歴の数字では分からない「なぜその使い方か」を本人に聞くこと。質問は必要な作業なので、遠慮せず必要なだけ尋ねる（承認の確認とは別物）。
ただし相手の負担を減らすため、1 回に 1〜3 問、短く答えやすく（選択肢＋自由記述）尋ねる。答えたくない・分からないときはその旨を記録して先へ進む。

## 進め方
1. 要約（重そうな要因と、履歴から読めた使い方）を見せる。
2. 固定質問から始める。
3. 回答と所見に応じて、重い要因ごとに深掘りする。「業務上必要そう／避けられそう／判断できない」を判断できる材料が得られるまで続ける。
4. 履歴だけでは判断できないことが分析中に出てきたときは、そのとき尋ねてよい。

## 固定質問
1. 主にどんな作業に使っていますか。具体的な作業内容を一般用語で一言で教えてください（例: LP のデザインガイドライン作成、ツール管理台帳の Excel データの集計と検知）。
2. 高いモデルや高い effort を選んでいる場合、その理由は何ですか（例: 難しい作業が多い、品質重視、なんとなく既定のまま）。
3. 履歴で見えた自動実行（`claude -p`・SDK・`/loop` などが `automation` に出た割合）について、何のために回していますか。止めてよいものはありますか。自動実行が見えなければ聞かなくてよい。
4. この端末の外（CI・クラウドの定期実行・ほかの端末・Web 版・別アカウント）でも使っていますか。履歴に残らないので、ここで聞く。

## 深掘りの例（所見に応じて選ぶ。これに限らない）
- 長いセッション: 1 つの作業をそのまま続けていますか、途中で別の作業を挟んでいますか。区切る機会はありましたか。`/clear` や `/compact` で区切ることはありますか（自動で圧縮されるまで続けていますか）。
- サブエージェント・並列実行: 並列にしているのはどんな作業ですか。意図して使っていますか。
- 大きなツール結果: 何を取得・読み込んでいましたか（Web ページ、大きなファイル、ログなど）。全部必要でしたか。
- 高いモデル・effort: 作業によって使い分けていますか。軽い作業でも同じ設定ですか。
- スキル・拡張: 意図どおりに起動していますか。関係のない場面で起動して困ることはありますか。
- 自動実行の中身: 固定質問 3 で出たものについて、頻度や間隔は必要ですか。結果は誰かが見ていますか。
- 履歴の欠損や他端末: 使い方が普段と違う期間でしたか。

## 記録のしかた
- 要点を一般用語で「利用者談」として書く。長い逐語引用は避ける。
- 必要なら固有名詞を最小限含めてよい。認証情報・秘密の値は書かない。
